Multi-tenant SaaS on Cloudflare, with isolation by construction

Rose is a security-first starter kit. Tenant isolation, passkey authentication, encryption, an operator console and a tenant app are done. You add your product as small modules, and the guardrails keep every change, human or AI-written, inside the security model.

What you get

The hard, easy-to-get-wrong parts of a multi-tenant product, finished and tested.

Isolation by construction

  • Every tenant has its own SQLite database (a Durable Object). No shared table to leak from.
  • The request host decides the tenant. Sessions, passkeys, API keys and codes are bound to one tenant.
  • The operator console runs in a separate Worker with no path to tenant data.

Modern authentication

  • Passkeys (WebAuthn) and emailed one-time codes. No passwords.
  • Host-bound __Host- cookies, server-side sessions, CSRF protection, rate limits.
  • Self-service signup, invitations, roles and scoped API keys.

Encryption

  • Per-tenant data keys wrapped by a master key (AES-256-GCM envelope encryption).
  • One-line field encryption bound to tenant and column; blind indexes for exact search.
  • Deleting a tenant destroys its key after a 48-hour grace period.

Two finished apps, one UI kit

  • Operator console: tenants, custom domains, operators, audit, background jobs, setup health.
  • Tenant app: onboarding, members, API keys, audit log, settings, and a Contacts module to copy.
  • Shared shell, drawers, paginated tables, confirmations, light and dark, in-app help.

Multi-tenant any service

  • A /svc gateway forwards authenticated requests to your existing service with a short-lived signed tenant token.
  • Or route to per-tenant Workers with Workers for Platforms.

Built for AI agents

  • AGENTS.md, skills, and hooks that run the guard after every edit.
  • Static guard rules that explain why and how to fix.
  • An isolation test contract that automatically covers every new module.

Tenant data and operator tooling never share a path. The control plane holds identity and routing only.

Status and limits

Rose is a starter kit, not a managed product. Before production, know that:

  • The production setup and deploy scripts are verified with --dry-run only in this repository.
  • The full passkey ceremony, live Cloudflare for SaaS calls and Workers for Platforms dispatch are not covered by automated tests.
  • Search on encrypted fields is exact-match. The edge rate limiter is per location.
  • No billing, file storage or per-tenant KV helpers yet.
  • The guard is a tripwire for drift, not a proof of security. The guarantees come from the per-tenant database, the typed module context and the isolation tests.
